Research Plan: Decentralized Avian Disease Monitoring via Federated Learning1. Project Overview & GoalObjective: To build and evaluate a privacy-preserving Federated Learning (FL) pipeline that classifies poultry diseases (Cocci, Healthy, NCD, Salmonella) from fecal images.Target Venue: Agriculture-Vision 2026 (CVPR Workshop).Core Innovation: Proving that decentralized training on isolated, diverse farm data can match the performance of a centralized model, even with a limited total dataset and lightweight edge models.2. Phase 1: Data Pipeline & Partitioning (Priority 1)Since our dataset is small, the way we partition and augment the data is critical to proving our system works.Tasks for Junior:Basic Preprocessing: Standardize image sizes (e.g., 224x224 for ViT), apply normalization, and implement heavy data augmentation (random rotation, color jitter, horizontal/vertical flips) to prevent overfitting on the small dataset.Create the "5-Farm" Simulation Splits: Write a script to split the training data into 5 distinct "clients."Split A (IID - Independent and Identically Distributed): Shuffle the entire dataset and divide it equally among the 5 clients. All clients have the same class distribution.Split B (Non-IID - Heterogeneous): Skew the data. For example, give Farm 1 mostly "Healthy" and "Salmonella" images, and Farm 2 mostly "Cocci" images. This is the most important dataset split for the paper.Deliverable: A PyTorch DataLoader setup that can easily toggle between Centralized, IID Federated, and Non-IID Federated splits.3. Phase 2: Model Setup & Baselines (Priority 2)We need to set up our core Vision Transformer (ViT) and introduce a lightweight alternative to prove this can run on farm edge devices.Tasks for Junior:Primary Model: Implement a standard, fine-tuned ViT (e.g., ViT-Base or ViT-Tiny pre-trained on ImageNet).Edge-Efficient Alternative: Implement a lightweight model for comparison. (Recommendation: MobileViT or Swin Transformer Tiny).Centralized Baseline: Write a standard PyTorch training loop to train these models on the entire pooled dataset. This establishes our "Upper Bound" accuracy.Single-Farm Baseline: Train models on only Farm 1's data to establish the "Lower Bound" (showing how poorly a model performs when isolated).4. Phase 3: Federated Learning Engine (Priority 3)This is the core of the project. We will use the Flower (flwr) framework since it is the industry standard for FL simulations.Tasks for Junior:Flower Setup: Wrap the PyTorch training loop into a Flower NumPyClient.Aggregation Strategy: Start with standard FedAvg (Federated Averaging).Advanced Aggregation (Optional but recommended): If the Non-IID data causes the model to crash or perform poorly, implement FedProx, which is specifically designed to handle heterogeneous data across clients.Deliverable: A script (run_federated.py) that spins up 1 server and 5 clients locally, runs for $N$ communication rounds, and outputs the global model weights.5. Phase 4: Evaluation & Interpretability (Priority 4)We need rigorous metrics to prove to the computer vision reviewers that our model is actually learning the right things, not just guessing.Tasks for Junior:Comprehensive Metrics: Accuracy is not enough. The evaluation script must output a classification report containing Precision, Recall, and F1-Score for all 4 classes. (False negatives are disastrous in disease detection, so Recall is highly important).Interpretability (Grad-CAM): Implement a script to generate Attention Maps or Grad-CAM visualizations for the ViT.Goal: We need to save 5-10 images showing the model's heatmap overlaid on the chicken droppings to prove it is looking at the actual disease markers, not the background sawdust.
